# cryo-web auth 502 — 2026-10-13

Login on `https://cryo-prod.penpencil.co` showed **Sign-in failed / Auth config
unavailable (502)**. The SPA loaded; only the API proxy hop failed.

## What it was not

- Not the FastAPI auth handler. `GET /api/v1/auth/config` returns 200 or 503,
  never 502.
- Not a down API. `cryo-api` was 2/2 Ready. From a web pod,
  `wget http://cryo-api:8000/api/v1/auth/config` returned 200
  (`mode=dev`, `dev_token_enabled_in_prod: true`).
- Not the GitLab digest in [`deploy/helm/cryo/values-prod.yaml`](../deploy/helm/cryo/values-prod.yaml).
  Live prod is Argo `production-cryo` on ECR `cryo-web-12` / `cryo-50`, chart
  `cryo-0.4.3`. The GitLab `web-latest@sha256:67ef838f…` pin (2026-09-30) is
  stale and is not what the cluster runs.

## What it was

Browser → ALB `cryo-ingress` → `cryo-web:80` → nginx on 8080 →
`proxy_pass $cryo_api_upstream` (`http://cryo-api:8000`).

nginx error log: `cryo-api could not be resolved (3: Host not found)` → HTTP 502.

[`web/nginx.conf`](../web/nginx.conf) in `cryo-web-12` used request-time DNS:

```nginx
resolver kube-dns.kube-system.svc.cluster.local valid=10s;
set $cryo_api_upstream http://cryo-api:8000;
```

Two independent failures:

1. **Wrong resolver.** This cluster runs NodeLocal DNSCache
   (`nameserver 169.254.20.10`). The kube-dns Service ClusterIP `172.20.0.10`
   exists and CoreDNS is Ready, but queries to `172.20.0.10` from the web pod
   time out. nginx was told to use `kube-dns.kube-system.svc.cluster.local`,
   which is that unreachable ClusterIP.
2. **Short name.** nginx does not apply `/etc/resolv.conf` search domains.
   `cryo-api` via 169.254.20.10 is NXDOMAIN.
   `cryo-api.cryo.svc.cluster.local` resolves to the Service ClusterIP.
   glibc (`wget`) succeeds on the short name because of
   `search cryo.svc.cluster.local`.

`resolver local=on` is **not** valid on nginx-unprivileged 1.30.5 in this
image (`host not found in resolver "local=on"`). `resolver 169.254.20.10`
passes `nginx -t`.

## When it changed

| When | What |
|---|---|
| 2026-10-06 19:04 UTC | `cryo-web-11` ReplicaSet created. Bare `proxy_pass http://cryo-api:8000` resolved at **startup**. |
| 2026-10-08 19:43 IST | [`ff2e5691`](https://github.com/tech-pw/cryo/commit/ff2e5691) deferred DNS to request time because web-11 crash-looped (`host not found in upstream "cryo-api"` at boot, 396 restarts / 33h). Hardcoded `kube-dns` + short name. |
| 2026-10-12 | [`e00db3a7`](https://github.com/tech-pw/cryo/commit/e00db3a7) listen 80→8080 / WS upgrade filter. Resolver unchanged. |
| 2026-10-13 13:18 UTC | Current `cryo-web-12` pods started. That is when the 502 began. SPA stayed up because `/` is local `try_files`. |

Do **not** revert to startup `proxy_pass`. That crash-loop returns.

## Durable fix (this change)

Keep request-time DNS. Stop baking kube-dns.

- [`web/nginx.conf`](../web/nginx.conf) is an envsubst template:
  `resolver ${NGINX_LOCAL_RESOLVERS} ipv6=off valid=10s` and
  `set $cryo_api_upstream ${CRYO_API_UPSTREAM}`.
- [`web/Dockerfile.prod`](../web/Dockerfile.prod) copies it to
  `/etc/nginx/templates/default.conf.template` and sets
  `NGINX_ENTRYPOINT_LOCAL_RESOLVERS=1` so nginx-unprivileged's
  `15-local-resolvers.envsh` exports the pod nameserver.
- Helm [`web-deployment.yaml`](../deploy/helm/cryo/templates/web-deployment.yaml)
  sets `CRYO_API_UPSTREAM` to
  `http://{{ fullname }}-api.{{ namespace }}.svc.cluster.local:{{ service.port }}`.

Prod remediation is a **new cryo-web image** rolled by Argo, not a
`values-prod.yaml` GitLab digest bump.

Verify after roll, from a web pod:

```sh
wget -S -O- http://127.0.0.1:8080/api/v1/auth/config
```

Expect HTTP 200. The login form will still be username/role while
`CRYO_ALLOW_DEV_TOKEN_IN_PROD` is true; that is separate from the 502.

## Immediate mitigation (no image)

The baked `default.conf` is not a ConfigMap. Until the new image is live,
rewrite the resolver + FQDN in each web pod and `nginx -s reload`. A pod
restart restores the broken baked conf.

Applied 2026-10-13 15:33 UTC on `cryo-web-9db6975fb-9pk4j` and
`cryo-web-9db6975fb-x5k9d`:

```
resolver 169.254.20.10 ipv6=off valid=10s;
set $cryo_api_upstream http://cryo-api.cryo.svc.cluster.local:8000;
```

After reload, `wget http://127.0.0.1:8080/api/v1/auth/config` returned 200
(`mode=dev`, `dev_token_enabled_in_prod: true`). The first request during
reload can 499/502; wait for workers to recycle.
