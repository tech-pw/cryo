# Cryo Premortem — Actionables

Companion to `docs/PREMORTEM.md`. Each item traces to a specific scenario there. Prioritized by
blast radius if left unfixed for 6 months, not by implementation effort. 🔴 P0 = fix before any
real deployment; 🟡 P1 = fix before scaling past a small/trusted fleet; 🟢 P2 = hardening, do
opportunistically.

**Implementation status (2026-07-05):** All 🔴 P0 backend and UI items below are implemented in
code (JWT auth, secret encryption, native engine gate, bandit fix, PII fail-closed, Helm chart,
Popconfirm on destructive actions, signed frontend tokens, error alerts). 🟡 P1 items are mostly
done except OpenTelemetry, full dashboard pagination, shared formatter migration, and backend-only
feature UIs (documented in `docs/DEPLOYMENT.md`). 🟢 P2 items remain open. See the remediation
table in `docs/PREMORTEM_FEATURES.md` for per-finding detail.

**Suggested sequencing:** do all 🔴 P0 items before recommending Cryo for any deployment beyond a
single trusted operator's own fleet — these are the ones where "it mostly works" is actively worse
than "it doesn't work yet," because they fail silently and expose real blast radius (auth, secrets,
tenant isolation). 🟡 P1 items are what determines whether Cryo holds up once real users show up
at real fleet size. 🟢 P2 items are what keeps the current good trajectory from degrading as
velocity continues.
