Grades

Every table starts at 100 points and loses points for each problem the scan finds. The grade is the letter for the final score. The home chart counts tables per grade. It is not a size-weighted median. UI words map to letters: A Excellent, B Good, C Fair, D Poor, F Critical.

GradeScore
A90 or more
B75 to 89
C60 to 74
D40 to 59
FBelow 40

The home screen rolls those grades up across the lake, so you can see at a glance how many tables need work and how much storage maintenance could give back. It shows whether the count of D and F tables moved since yesterday, which D and F tables people query most, and which tables Cryo moved up a grade in the last 24 hours. A table only counts as fixed once a scan after its maintenance job shows the better grade. The quickstart shows that screen after the first scan of the seeded lake.

Deductions

There are two deduction sizes and no others: a warning costs 8 points and a critical finding costs 20. Two warnings and one critical is 100 − 8 − 8 − 20 = 64, grade C. The seeded demo run is the same lake, not a production fleet.

Projection: from scan to stored cost

The cost estimator turns the scanner's stored statistics into a projected byte count for each operation and stores it. Nothing is read from object storage to produce it. Orphan-file precision is an opt-in scanner tier. Without it, the number is flagged as last-known.

Projections are byte classes: live data, expirable, manifests and metadata, and orphan candidates. The bytes are what Cryo measures. The Cost & Savings tab multiplies them by the AWS S3 Standard rate to show a monthly figure, labelled as modelled. For a table outside S3 it shows bytes only, because the rate wouldn't apply.

What each operation projects

OperationProjected effect
expire_snapshotsBytes referenced only by snapshots the retention policy would drop, and only when no surviving snapshot still references the file.
remove_orphan_filesBytes present in storage but referenced by no snapshot. Precise only on the scanner's opt-in listing tier.
optimizeDelete-file bytes merged away. Data bytes are rewritten, so the storage change shows up in the later expiry projection.
optimize_manifestsManifest and metadata bytes reclaimed by consolidation. Small in volume, large in plan-time latency.
